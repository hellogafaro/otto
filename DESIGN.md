# Foundation

The authorized source replacement uses the bb application components. The subsequent shell direction replaces its icon rail with one sidebar beside a large main panel and adopts the measured Capy neutral palette and compact control scale, with a Tailwind sky accent. It does not restore the deleted v1 Otto UI or its previous token values. `apps/app/src/components/ui/theme.css`, `apps/app/src/app.css` and the shared UI package remain the implementation sources for colors, typography, spacing and interaction states. Preserve light/dark themes, responsive navigation, focus states and accessible control names.

# Application shell

Use one sidebar, not an icon rail plus a second sidebar. Its ordered regions are: owned Otto logo with a functional search control at the right; labeled primary navigation; populated Pins; populated Recents; and user navigation anchored at the bottom. Empty groups disappear completely, including their headings, placeholders and unused spacing. Determine emptiness from the currently eligible visible rows, not stale saved group membership; preserve saved groups and preferences. Pins and Recents use existing thread data and pin operations, not invented entries or a second persistence model. Keep the bottom region reachable while the middle content scrolls.

The main panel takes the remaining space and uses existing surface, border and radius tokens. Settings replaces the normal sidebar with Settings navigation and a Back to app control; it does not keep the global navigation, Pins and Recents visible or add a second left column inside the panel. Returning restores the normal sidebar. Screens that need contextual controls, such as Skills, can use an internal right sidebar within the main panel; do not add one to every screen. On narrow screens these contextual controls may use a compact menu. Remove every visible left-sidebar toggle button and the space reserved for it, including footer, overlay, compact and native-chrome variants. Keep right-panel controls separate. Preserve resizing, keyboard/command access, compact swipe navigation, native traffic lights/window dragging and plugin-contributed navigation/disclosures. Use current capabilities only: a missing human identity gets an honest generic account control, not a fabricated profile or nonfunctional authentication actions.

The desktop app (only where `window.desktopBridge` exists) adds Capy's titlebar tabs as one 34px row (`--app-titlebar-height`: the 6px panel gap above 28px tabs; 0 in the browser, which keeps its layout and shows no strip), so the tabs sit the same 6px panel gap from the window top, from each other and from the panels below. The host owns the shared typography scale. Loading retained plugin CSS must not reset the app's font sizes or weights through an older Tailwind theme layer. Keep responsive overrides and deliberate custom styling functional; regenerate the public registry and plugin theme bridge when their source tokens change.

Primary buttons use sky 700 fills and white labels in both appearances through dedicated solid-action tokens. Keep sky 500 for dark-mode foreground accents; do not darken those foreground accents to match button fills. Disabled controls, decorative dividers and muted metadata are distinct from active text. Both clients render the same canonical shared palette rather than independently selecting optional themes.

Accessibility takes precedence over exact shade matching: muted text mixes 65% ink in light mode and 70% in dark mode, rather than the reference's 62%/68%, to remain readable on hover/active surfaces. Preserve the fork's stronger subtle/readback tiers rather than copying Capy's faint tertiary shades. Input boundaries use 50% ink in light mode and 45% in dark mode, independently of decorative hairlines. # Typography and control geometry

Keep the existing openly licensed Inter variable font. Desktop regular text uses weight 450, controls and navigation 500, and semibold emphasis 560. The compact scale is Linear's: 11px metadata, 12px small controls (`text-xs`), 13px body, navigation, controls and composer pickers (`text-sm`, the base everything adapts from, as in Capy and Linear), 15px titles and section headings (`text-base`) and 18px larger text; the named steps stay in rem so the Appearance size setting scales them. Small text uses line heights 1.3 and 1.25; body uses 1.5, with the measured compact composer at 1.2. Use subtle tracking: −.01em on 13px and −.02em on body/larger text. Do not make all labels semibold.

**Dictation.** An empty composer's send slot is the mic. While recording, + turns into × (Cancel dictation), the row fills with the voice as 4px squarish bars 2px apart that rise with the mic level mirrored from the center, then the elapsed time, and the slot turns into a destructive stop. Stopping disables the slot with a spinner while the recording is transcribed, and × still cancels. A failure is the toast "Dictation couldn't be completed" with the reason and a Retry action that transcribes the same recording again; the slot goes back to the mic, or to Send when there is a draft.

**Working and failures.** While a bot works, one line under its avatar says what it is doing and counts the elapsed time. A provider that goes quiet for a while never turns that line into a warning such as "No response from …"; only a real failure shows, as the chat's error card at the end of the transcript, with the provider's own message once and never behind an internal prefix.

Models (/settings/models, formerly /settings/providers; /settings/models/<provider> redirects to it) is one Connections card like Capy's: a count row ('2 connections') whose plus menu signs in to a provider or adds the Custom API, then one row per connected account only (logo tile, account title, plan or Main account / Backup n). Several accounts of one provider are allowed; the first ready one serves and the next takes over at a limit, reordered with up and down buttons that appear only when a provider has more than one. A row has a ghost Remove, a trailing switch that turns the account off without signing out (requests skip it; its detail reads Turned off; with every account off the provider reports disabled), and, only when something is wrong, an error or warning badge plus one fix (Try again, Sign in again, Replace key). A Defaults card below holds Default model: the model picker and its traits picker (thinking level, speed such as Fast where the model offers it); new bots start on it and bots without their own model follow it. Sign-in, API keys and the Custom API (base URL, key, model IDs) open in dialogs. There are no per-provider pages, instances, accent colours, environment variables or model tables. Images (/settings/images) follows Voice: one Image generation card with a one-line note that chats cannot create images yet, a row per image provider (ChatGPT, Grok) that reuses its Models connection with a switch, which Connect (or Sign in again) replaces while the connection is missing or signed out, a badge only on failure, and a Default provider select only when both are on (the other is the fallback). Channels (/settings/channels) is not part of the MVP: the page keeps one Channels card listing each channel (logo tile, name, tagline) with a quiet Coming soon badge and no links, buttons or setup pages; /settings/channels/<channel> redirects to it, and the bot settings Channels row shows the same badge. A person who starts a new call while their own earlier call is still open (a reload or a lost hang-up) replaces it; someone else's open call still blocks with A call is already active.

Computer (/settings/computer) is two short cards. Every bot always gets its own computer (its own files and browser logins), so there is no Workspace card and no shared-computer option. There is no Local execution setting: bots always run with full access, because sandboxes are what contain them, so no approval mode picker and no Enable auto review on approvals. Sandboxes is built like the Models Connections card: a count row ('0 sandboxes') whose plus menu lists the cloud sandboxes not yet connected (E2B, Daytona, Vercel Sandbox, Railway, Boat), one row per connected sandbox (logo tile, name, description, ghost Remove, outline Edit), and a Default sandbox row only once a cloud sandbox is connected; with none, one line says bots run on this computer. Credentials open in the shared `CredentialsDialog` (also behind `ApiKeyDialog` for Voice Providers): padded panel, one bare input for a single key or labelled fields for several, a dotted placeholder over a saved secret instead of helper copy, password managers told to stay out, ghost Cancel and a primary submit; save failures are a toast. Railway changes still pass its retire-VMs warning, built the same way. Browser holds one row, Bot browser access (a switch with no status line); there is no hosted browser provider. There is no auto-idle row, no always-listed provider rows, no Not connected or Available lines and no explainer tiles.

When the server's environment sets `BOAT_API_KEY`, Boat appears in Sandboxes as connected with the muted line "Connected by the server" and no Remove or Edit (the key is not the app's to change), and it can be the Default sandbox. A key saved in Settings still wins over the environment's.
