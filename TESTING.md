# Testing Otto

Run commands from the Otto repository root with Bun 1.4.2 or later. The runtime checks below use Vitest 5.0.3 under Bun, not `bun test` or a Node worker.

```sh
bun install --frozen-lockfile
bun run check
bun run typecheck
bun run check:boundaries
bun run check:consistency
bun run test
PLAYWRIGHT_SKIP_BROWSER_GC=1 bun --bun playwright install chromium
bun run test:browser
```

`bun run test` starts real PostgreSQL 18.4 from the pinned development binary package. Each suite creates a disposable data directory and a private 0700 Unix socket, disables TCP, runs native Drizzle push for declared public tables and pg-boss construction SQL, and stops its own process. It does not use a shared DB or require an Infisical secret. The test helper runs the binary package's symlink hydration script because that optional dependency setup is not executed by this Bun install. PostgreSQL fixture auth uses local trust inside the private socket directory; this is not production configuration.

The collaboration suite exercises Better Auth, bootstrap, invitations, workspace/project authorization and tasks. The Run suite exercises atomic rollback, exact snapshots, duplicate queue delivery, schedule reconciliation, Session scope and recovery fencing. The transport suite starts a real Bun HTTP/WebSocket server, uses Hono's typed client, and checks saved-history reconnect, current Document refresh, commit ordering, bounded frames and revocation. The content suite uses real PostgreSQL and a named in-memory storage fixture. That fixture tests metadata publication, immutability checks and retry behavior, not Garage durability.

Playwright tests use the actual Vite dev app and disposable authenticated backend. Do not run a production build for this local verification loop. Tests own their browser profiles and processes; never use the person's logged-in browser or stop an unrelated server. When the installed Chromium differs from Playwright's expected bundle, use the explicit executable-path fixture option rather than silently falling back to a personal profile. Screenshots against intercepted fictional HTTP responses establish layout only, not authentication or persistence.

Regressions must call production domain or transport paths and fail when the relevant guard is removed. Label controlled fixtures and missing proof. See [the implementation checkpoint](docs/execution.md) for the current evidence and external boundaries.

Mail acceptance uses `smtp-server` on ephemeral loopback ports and `mailparser` to inspect the actual MIME messages. `operations.test.ts`, `membership-transport.test.ts`, `invitation-mail.test.ts` and `runtime.test.ts` retain normal Better Auth signup, captured verification links, sign-in, reset and invitation permission checks. `smtp.test.ts` exercises partial configuration, mandatory encryption, authenticated TLS/STARTTLS, certificate and hostname rejection, AUTH failure/no-advertisement, redacted errors and a ten-second socket-closing deadline. Its temporary self-signed localhost certificate is generated by `openssl`; only child fixture processes trust it through `NODE_EXTRA_CA_CERTS`, never an insecure TLS option. No external SMTP service, mailbox or deliverability is qualified by these fixtures.

The combined runtime suite drives Better Auth HTTP, actual PostgreSQL/pg-boss, authenticated WebSocket replay, official native Mastra Sessions and controlled model tools. It includes elapsed-clock cron and Connection recovery; allow several minutes for the full suite. Those fixtures do not qualify a real model account, confined computer or Garage. The schema suite runs fresh development bootstrap and repeat push, checks stable definitions/data and queue-owned objects, and submits invalid cross-workspace/human/check/size writes. Native Mastra owns its separate PostgreSQL schema. The consistency scan is a naming/dependency/route check, not runtime proof.

Regressions cover stale Task owner edits and forged agent identity through actual HTTP/domain calls, common cursor validation, partial record updates and runtime closure during a blocked readiness query. Numbered app migrations are retired before MVP; retained offline-transfer fixtures establish only their exact disposable migration, not conversion of saved user data.

Execution regressions cover viewer control denial, immutable selected input/current tool scope, failed dispatch siblings, native cancellation during pending tools, unknown tool cleanup fences and actual Agent proposals/Task creation. Confined computer, script and steer execution are unavailable; removed Pi RPC/host-process assertions are recorded as retired capability, not equivalent native passes.

The pinned Drizzle Kit 0.31.11 introspector reorders composite FK metadata and can emit drop/add FK DDL on a repeat push. The current gate is semantic stability: no destructive approval, identical constraints/indexes/data, and unchanged native queue objects/jobs. Do not call that second command a no-op. Physical schema references may be cyclic; business-operation imports remain acyclic.

Visibility tests use real HTTP/auth/PostgreSQL/pg-boss with controlled native models/storage peers. They cover exact user/workspace enums, server ownership, filtered continuation, maintainer-only configuration, source revocation during I/O and active execution, member removal and disabled manual Schedule admission. Provider tests exercise explicit OpenAI Responses, OpenAI-compatible Chat Completions and Anthropic protocols through the official SDKs; controlled peers do not prove real login or billing.

The old managed gateway and Pi packages are removed. No Go gateway helper, subscription OAuth flow or host process runner is a prerequisite for current native acceptance. Real-provider smoke tests are separate, explicitly authorized, bounded by request/token/deadline limits and restricted to fictional isolated app data. Inject credentials in process memory; never write them, request bodies, raw provider errors or browser network traces into evidence.

The Skills split is exercised by `skills-transfer.test.ts` (explicit private-DB transfer/refusal and unchanged accepted evidence), plus Skill HTTP/visibility/proposal and bounded native supporting-file materialization cases. Document payloads reject retired Skill fields; ordinary Document proposals/Collections remain separate. See [Skills model and transfer](docs/skills.md).

Task assignees and recurrence are exercised by `task-assignees.test.ts` (authenticated HTTP and private PostgreSQL: mixed selections, replacement/clear, eligibility denials with no side effects, canonical IDs, bounds, filters/pagination, concurrent stale edits, FK/uniqueness), `task-assignees-transfer.test.ts` (the explicit private-DB `scripts/move-task-assignees.sql` plus repeated native push) and `task-recurrence.test.ts` (Date-only fake clock; acceptance dates, one-successor fence, COUNT/UNTIL/INTERVAL anchor, DST/month end, eligibility and rollback, strict HTTP validation). See [Tasks](docs/tasks.md).

Native account tests cover authenticated key replacement, member/private visibility, creator/status revocation, exact endpoint/model/credential identity and sponsor-private Sessions. `run-usage-cost.test.ts` records observed native token usage; an unavailable price remains unknown, never zero or an asserted account charge. Native compaction and real billing are not established by retired Pi evidence.

The historical `chats-transfer.test.ts` depended on retired Pi/computer execution and is no longer part of the native suite. Its source remains recoverable from the pre-native checkpoint; `scripts/rename-chats.sql` remains an explicit offline recovery script, not an automatic saved-data conversion. Current Chat authorization, native history, publication and continuity have separate domain/transport/runtime tests and source-hashed acceptance evidence. See [Chats](docs/chats.md) and [native acceptance](docs/native-acceptance.md).

The Resources → Files rename is exercised by `files-transfer.test.ts` (private PostgreSQL: the explicit `scripts/rename-files.sql` refusal cases for busy Runs, mixed state, leftover attachment columns, mixed Task-link discriminators and un-renamed Chats; unchanged IDs/rows/object keys/upload request JSON, accepted Run, Session, retained scope, Skill, frozen-share and native queue bytes; constraint/index/column names and definitions equal to a fresh push; exact upload retry with one storage put and conflicting retries; Resource- and Artifact-era Skill/share forms projected at their owning boundaries; accepted supporting-file retrieval; real runtime-produced prompt and script scopes still binding new Runs, an Agent `file.create` publication, and a changed source set still refused), the full sequence in `resources-transfer.test.ts` (Artifacts → Resources → Files), `file-immutability.test.ts` and the retired-route/field cases in the content and authorization suites. See [Files](docs/files.md).

Discovery lists are exercised by `lists.test.ts` and `lists-domains.test.ts` (real HTTP, Better Auth and private PostgreSQL; fixed disposable cursor secrets): order before the limit over 130 rows with the newest at the end, id order and the 100 default/maximum, microsecond ties, NULLs last in both directions, case-insensitive full-title order beyond 100 characters, continuation after the cursor row is deleted, strict refusal of unknown keys/injected sorts/`order` without `sort` on every list, sealed cursors that never carry a hidden row's title and that reject another person, workspace, operation, filter, sort, tampering and a rotated secret (valid across a restart with the same secret), cursor sizes for the widest supported Unicode titles through the library prefix, plus per-domain sorts and filters, Document/File labels (default `[]`, bounds, token and custodian rules, immutable upload request, retry after a label edit, frozen shares) and the unchanged replay/attention/fixed contracts. Readable-rows-only listing is exercised by `lists-privacy.test.ts` (an oracle: a reader's pages, empty-page pattern, next presence and cursor lengths are identical with and without hidden rows of very different lengths), `lists-authority.test.ts` (domain level, real PostgreSQL: for each list and caller, including Agent actors with a sponsor who is not a participant, the ids of a complete walk in id order and both sorted orders equal the ids `getX` allows) and `lists-lock.test.ts` (every kind of authority write blocks while a list read transaction is open). Sensitivity was checked by loosening or tightening a rule, removing the fail-closed path and removing the read lock, each of which fails a test. See [Discovery lists](docs/lists.md).

Folders, larger uploads and verified downloads are exercised by `folders.test.ts` (real HTTP and private PostgreSQL: nesting, depth and cycle limits including a concurrent crossing move, placement and privacy rules, empty-only archive with hidden children, first-placement wins, mixed library paging and Project roots, atomic mixed edits with no cursor movement; mutation checks fail when the cycle, emptiness or user-folder rules are removed), `uploads.test.ts` (the real `apps/server/src/index.ts` process, the real AWS client and a controlled S3-compatible HTTP peer: 50 MB and 100 MB round trips with measured server memory and one storage put, 100 MB + 1 refused by header and by chunked stream, short and abandoned bodies, denial before any body byte, exact/changed/concurrent retries, lost storage acknowledgement and storage failure, corrupt and truncated storage, revocation during storage I/O and during delivery, abandoned downloads, simultaneous transfers beside unrelated requests, small-consumer bounds, public frozen downloads and a full disk) `file-delivery.test.ts` (fast, no database: verified delivery, a final-chunk and an interval authority re-check, the total deadline, the stall limit, an unconsumed body, cancellation and joined descriptor release, each with a mutation that turns it red) and `spool.test.ts` (budget admission, ownership-safe cleanup of abandoned instance directories, receive idle/total deadlines). `uploads.test.ts` also covers HEAD without storage or spool use, no descriptor leak after storage failures and resets, silent corruption and a lost acknowledgement over it, a 37 s storage verification beyond Bun's idle timeout, 100 MB anonymous HEADs, measured revocation disclosure, trickling/silent uploads and, on raw sockets, that completed or refused transfers close their connections (`Connection: close`) rather than idling forever. Fixture scope only: the peer is not Garage and proves no durability. `uploads.test.ts` keeps every uploaded object until its peer stops (about 1 GB at peak) in the temporary directory, so it needs that much free space: point `TMPDIR` at a disk if `/tmp` is a small tmpfs.
