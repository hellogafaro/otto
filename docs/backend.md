# Backend implementation notes

The server composes fourteen Bun workspace packages, including generated UI, database plumbing and workspace authorization. Projects, Tasks, Conversations, Documents, Artifacts, Agents, Environments, Sessions, Runs, Connections and Automations own their operations. Collections and skill snapshots use Documents. The dependency check rejects cycles and private schema imports between domains. Cross-domain foreign keys are composed in a migration.

## Transaction and transport behavior

The HTTP API uses Better Auth sessions, current workspace membership, Zod inputs and same-origin writes. Workspace transactions lock the workspace row before checking membership and mutating records. This serializes permission changes and cursor advancement until commit. Reads for WebSocket delivery retain a shared lock through enqueue, so removal cannot commit between the access check and that enqueue. This is a simple initial consistency choice, not a measured scalability result.

The server limits concurrent HTTP requests to 128, bodies to 1 MiB, database connections to 10, statements to 10 seconds and Environment admission queues to 20 attempts. WebSocket subscriptions recheck auth and access every second, page history, bound frames/buffers to 1 MiB and explicitly snapshot requested Task/Document views on reconnect. A workspace revision change refreshes current views. This is polling behind the planned authenticated WebSocket, with no LISTEN/NOTIFY or third-party sync selection.

`apps/server/src/api.ts` exports `RpcApp`, used by Hono's `hc` client in the live transport test. There is no duplicate contracts model. The web remains the requested generated boilerplate, so product routes, TanStack caching and Tiptap UI are not introduced yet.

## Queue ownership and recovery

Drizzle owns domain migrations. pg-boss 12.35.1 owns `otto_jobs`; deployment migration uses its exported construction SQL, and runtime sets `migrate: false` and requires installed queues. Run admission uses the library's `fromDrizzle` adapter to save the exact inputs, optional fresh private Session and dispatch job in one transaction. It also saves normalized caller controls separately from resolved source contents. Every RunRequest field participates in retry identity; omitted skill IDs mean Agent defaults while an explicit empty list means no skills. An exact retry returns its original snapshot after checking current Conversation access. Changed controls conflict before admission side effects. Legacy rows without recoverable request identity fail closed on retry; migration 0004 adds the nullable field without inventing historical controls.

Inspection of the pinned package found that `schedule()` uses its own database even when an admission adapter is supplied. Automation edits therefore enqueue durable schedule reconciliation in their domain transaction. Reconciliation reads current config under the workspace lock. Scheduled payloads carry a config token, and stale/paused deliveries are recorded without admitting work. Manual Run stays available when an Automation is paused. One outstanding Run per Automation is also enforced by a partial unique index. Named timezones and `missed: skip` are supplied to pg-boss.

Dispatch rechecks the sponsor, audience, source permissions, agent configuration, Environment generation and Connection grants. Without a selected compute backend it records `failed / compute_provider_not_selected`. It never launches a local process. Startup recovers queued bookkeeping and marks potentially launched executions uncertain. Stale attempt updates are rejected; an uncertain remote process is not declared stopped. Tests simulate those database states and do not prove remote reconciliation or process isolation.

## Content and external boundaries

Documents reject stale edit tokens and store one current body. Restricted Documents and Artifacts deny agent actors because no explicit agent-grant mechanism exists. Human-authorized Run skill snapshots remain a separate admission path; an agent cannot inherit its sponsor's direct private reads. Collection fields retain IDs and validate their types. Skill instructions are copied into Run inputs; later edits do not mutate the accepted snapshot. Session scope includes selected skill IDs so a caller cannot silently drop a previously retained source while reusing context.

Artifact metadata records upload intent before S3 I/O and exposes only saved records. Metadata, library listing and private reads require both current access and the immutable source-Run audience when present. Reads reauthorize after storage fetch and check byte length/hash. Library pagination advances over at most 100 scanned candidates even if some are filtered by source audience. Retry identity pins one object key and byte hash; source-Run outputs cannot be widened to a larger human audience. The adapter sends conditional immutable writes and private reads. Artifacts currently save one file per record. The JSON transport accepts at most 700,000 base64 characters; the domain storage limit is 8 MiB. No public bucket URL or executable HTML preview is returned.

Connections hold account metadata and scoped resource/action grants. Disconnect revokes grants and changes configuration. Disconnected records are ineligible for grant, snapshot, operation request or approval even if an unrevoked grant row remains. Account registration starts disconnected; no provider connection/reconnect route exists. Tests that exercise active grants seed connected metadata explicitly and do not prove provider connectivity. Exact operation target/account/approval and uncertainty records exist, but no provider executor is connected. No GitHub/MCP operation or native subscription login has been qualified. Native credentials must remain in the selected isolated Environment.

## Runtime boundaries still open

- No verified Otto Infisical project/environment/path was available. Nothing was linked or read from another project. Production server setup needs the verified scope for `DATABASE_URL`, `BETTER_AUTH_SECRET` and `OTTO_ORIGIN`; S3 additionally needs `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID` and `S3_SECRET_ACCESS_KEY`.
- Before wiring a tool/external executor, trusted Run composition must verify the operation Run is live and belongs to the input Agent. `requestOperation` has no production caller/executor today; Connections cannot import Runs without creating a cycle. Environment claim/uncertainty operations also need production-bound single-active-Run, generation and uncertainty tests when a provider dispatch caller exists. These are Cody's future integration prerequisites, not qualified execution behavior.
- No compute backend has been selected. Native ACP control, two independent isolated computers, subscription mode/account checks, quota behavior, remote deadlines, process-tree Stop and VM recovery remain unavailable.
- Better Auth registration/login is exercised. Invitations require verified email, but a production email-verification sender and account recovery delivery are not configured.
- Garage/S3 service compatibility, conditional writes, durability, restore and deployment are unverified. Pending uploads retain durable retry intent; an operator cleanup policy is not implemented.
- Cron schedule installation/edit/pause and duplicate occurrence admission are exercised. Wall-clock cron firing, DST, outage recovery and performance under load are not certified.
- Generated web UI only. Rich editing, public shares, selected supporting skill files/import/export, directed native peer execution and full product workflows are outside this implemented checkpoint. These are not reported as working features.
