## Transactions and transports

Better Auth supplies human identities. Ordinary signup and sign-in need no mail or mandatory email verification; neither proves email ownership. Invitation acceptance requires the emailed private token and current recipient/issuer authority. Password reset, session revocation and explicit invitation delivery retries retain their concrete boundaries. Workspace transactions lock the workspace before checking current membership and writing. Human owners remain separate from the zero-or-many human/Agent assignee sets ([Tasks](tasks.md)); only authorized humans mark Tasks Done. Agent tools derive identity from the persisted Run, never a browser-supplied agent ID.

Hono RPC retains inferred input/output types. One server error boundary translates expected errors; validation middleware sends invalid inputs there without returning validator data. Ordinary discovery uses `{items,next}` with a null terminal cursor, typed filters, exclusive cursors and a default/max limit of 100. Queries fetch one extra candidate; authorization filtering preserves scanned continuation even for empty pages. Numeric message/activity replay and complete authorization snapshots retain separate ordering and completeness guards. See the canonical [code principles](otto/code-principles.md).

Authenticated WebSockets recheck sessions and current access, replay saved messages/Runs/activity and refresh requested current Task/Document views after a gap. Shared database locks extend through enqueue. Transport uses bounded polling, not a selected LISTEN/NOTIFY or third-party sync system. Connections are capped at 500 overall and four per user, frames/buffers at 1 MiB. HTTP allows 128 concurrent requests and 1 MiB bodies; the database pool has ten connections and ten-second statements. These limits are not throughput guarantees.

## Queue, execution and recovery

Native Drizzle push owns the current development schema; there is no numbered application migration chain before MVP; pg-boss 12.35.1 owns schema `queue`. `startQueue(db,pool,{workers,install,runtime,harnesses})` uses the library's construction and transaction APIs. An existing `otto_jobs` schema causes an explicit migration refusal; no tables or outstanding work are silently abandoned. Run, exact request identity, immutable inputs, optional Session and dispatch admission commit atomically. Retries return the original accepted snapshot or conflict on changed caller controls. Legacy unknown identities fail closed.

pg-boss `schedule()` cannot use the admission transaction. Schedule changes therefore enqueue atomic durable reconciliation. Current config and occurrence identity fence stale/duplicate delivery. Prompt/script Schedules use the same runtime as manual Runs, with named timezones and `missed: skip`. Scheduled delivery requires enabled status; disabled still permits explicit owner-authorized manual execution. Edit/archive fences unlaunched work; accepted active work still supports output, answers, steer and Stop. Source archive is launch eligibility, not permission revocation. Current sponsor, scope, audience, grant and attempt checks continue throughout execution.

The trusted server accepts a capability-checked `ComputerBackend` and installed harness commands `{version,argv}`. Admission resolves `harnessVersion` from this server configuration; Agent create/edit has no installation-pin field. Missing configuration rejects new prompt admission explicitly, while an exact retry retains its originally admitted Run. It persists launch identity before I/O, reserves at most sixteen active/preparing executions, claims one Environment lease with a unique provider/computer binding, bounds ACP/script I/O and deadlines, and records lost acknowledgements or unconfirmed Stop as uncertain. Lookup reconciles a launch without blindly repeating it. Stop/recovery cannot release a lease while launch is pending; absent lookup after a lost acknowledgement is not proof that a delayed launch cannot arrive. Shutdown persists unjoined server-tool uncertainty before detaching local handles. Sessions bind opaque provider context once; account/model selection and retained scope cannot silently switch. ACP v1 and the explicitly negotiated Otto tool/steer extension are exercised with controlled processes only. No host subprocess is offered as an isolated computer.

Scoped tools support messages, accepted-only Document/skill reads and edit-token proposals, Task reads/proposed completion and creation with the sponsoring eligible human owner, directed peer admission, human questions/answers, Connection operations and File creation. Peer requests have depth, child-count and rate limits. Skill bodies and immutable file references are copied at admission and materialized with current authority checks. User skills can retain restricted supporting bytes; widening skill visibility must preserve every file recipient cap, and materialization rechecks it after storage. Task reads use accepted title/notes while still checking live authorization. Agent File creation requires trusted sponsor/Run/attempt/launch/Environment checks before and after storage and returns an immutable creation receipt.

External GitHub/MCP Connections implement deliberate connect/discovery/disconnect/reconnect, exact account/resource/action/recipient approvals and GitHub/MCP protocol boundaries. The server validates a narrow Run proof plus equality of the entire accepted/current grant map; Connections checks each operation before/after I/O. Protected writes retain uncertain outcomes after lost replies or revoked publication. Server-owned recovery scans at most 101 candidates and transitions 100 under workspace locks with token/state/age fences. Startup drains backlog; a minute pg-boss schedule recovers claims that become stale later, including removed sponsors, without provider replay or forged user authority.

## Configuration and visibility

Agents, Skills, Documents, Files, Connections and Subscriptions use exactly `user` / `workspace` visibility and server-derived `createdBy`. Eligible workspace readers/users do not become maintainers. Documents/Files have one visibility setting with creator/custodian-only edits; per-user collaborator ACLs are deferred. Current Run checks intersect accepted scope with live visibility, membership and grants, including after I/O. Content audiences also intersect current Project/workspace membership; accepted recipients never bypass current source access. Explicit Chat viewers remain read-only even with inherited access, including executing Agents. Public frozen-share publication remains a separate explicit human action.

Agent reusable skills persist in the workspace-safe `agents_skills` junction; bounded skill IDs are input/projection only. Agent owns reusable skill selections and Connection grants. Projects/manual Runs have no skill overrides; Schedules have no skill/Document/message arrays. Bounded manual selected Documents/messages/Tasks remain execution content with immutable accepted and retained-source fences. Schedule status is enabled/disabled/archived; disabled blocks cron while manual owner execution remains available. One token-checked update owns status/configuration/owner edits. Restore is disabled. `schedule_history.id` uses native delivery identity for skipped/deduplicated outcomes; execution history belongs to Runs.

Numeric guards have concrete jobs: record edit tokens reject stale human edits/proposal application; Agent/Schedule configuration tokens fence queued launch; Connection edit/grant generation pins exact approval and accepted policy; Run attempt/launch key and Environment generation fence delayed I/O. Cursor is replay ordering. None is a user-facing version history.

## Content, storage and errors

One API entry owns human authentication, write-origin checks, dependencies and workspace transactions. Static collaboration, content, execution and Connections route groups preserve Hono RPC inference; anonymous frozen shares mount before auth. Ordinary partial record edits use an allowlist. Document/skill content, Task ownership, Collection structure and execution configuration retain their concrete edit fences. Project/Chat/File metadata and Subscriptions need no client token; Connection title-only edits preserve policy tokens and grants.

Documents, Collections, immutable supporting skill files, proposals, search, attention, archive/restore, scoped content links and selected frozen public shares are mounted through one authoritative route per method/path. Restricted direct Document/File agent reads remain denied. Private source-Run File metadata/list/read require both current access and the saved audience; eligible human owners may explicitly publish a selected frozen share. Public reads recheck publisher authority; revoked shares return not found, while dependency outages propagate.

File intent and request identity precede storage I/O. Object keys include intent identity and digest; Garage's ignored conditional headers are not relied on. Exact retries reconcile hash and length; changed bytes cannot overwrite the referenced key. Reads validate integrity and reauthorize after fetching. Existing legacy objects remain readable/retryable; missing legacy objects require operator recovery. HTML public previews use sandbox/CSP without scripts or credentials.

Errors propagate, become explicit boundary failures, or leave durable retry/uncertain state. Cleanup preserves original failures and releases remaining resources. An MCP cleanup failure after a committed write is reported, while the saved outcome prevents replay. The normalization audit and production-seam regressions are recorded in [current evidence](evidence/backend-review-validation.txt).
