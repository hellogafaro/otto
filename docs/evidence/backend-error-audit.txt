Current backend error audit, 2026-10-02
Scope: all handwritten packages, apps/server/src and scripts. Tests and generated/vendor code are not production handlers.

Audited outcomes:
- shared: filterPage suppresses only forbidden records and retains scanned cursor; withCleanup propagates primary errors and aggregates cleanup failure; invalid domain parsing produces DomainError without invalid values.
- server app/config: parser predicates reject invalid config; readiness returns unavailable/503; one HTTP error boundary translates expected failures and redacts unexpected ones. All API validation middleware routes failures through that boundary.
- server content-presence: only absent/forbidden current participants are evicted; database/unavailable failures propagate.
- server content-shares: only absent/forbidden publication is hidden as 404. A reproduced unavailable storage response now remains503, then recovers to200.
- server content-api: independently absent/forbidden linked records are filtered while preserving scanned continuation; other errors propagate.
- server realtime: terminal authorization/protocol/dependency failures close the socket explicitly; no fabricated replay-success/empty history.
- server mail/invitations: provider details are redacted; durable invitation remains; delivery is explicitly sent/unavailable/uncertain, never implicit retry or another recipient/account.
- server queue: failed jobs propagate to pg-boss bounded retry; exhausted queued Runs get fenced terminal state; partial startup always stops its acquired boss and retains both errors if cleanup fails.
- server lifecycle/index: cleanup attempts all acquired resources, records failures and exits/throws; forced drain rejection is observed. Startup/shutdown configuration errors are redacted and process exit is nonzero.
- scripts migrate/health: nonzero failure exit. Migration advisory unlock failure deliberately discards its session, which releases the lock; it does not fabricate migration success.
- automations: malformed cron is invalid input; revoked schedule authority unschedules; rejected occurrences persist an explicit reason instead of claiming admission. Database failures retry through queue.
- connections HTTP/GitHub/MCP: exact known protocol/credential failures translate without provider values. Reader cleanup retains original errors and releases locks. MCP DELETE ignores only expired404/unsupported405; other cleanup failures propagate. A committed write remains succeeded and cannot replay after cleanup failure.
- connections server: post-I/O failure records failed/uncertain with no unauthorized publication. If membership removal prevents recording, durable executing intent is recovered by server-only recovery. Cleanup waits for the transactional outcome and cannot erase it.
- documents skill parser: invalid frontmatter is a typed invalid error; no parser detail leaks.
- runs admission/fallback: authorization/configuration failure becomes durable terminal state, with removed-sponsor server fencing; arbitrary database errors propagate.
- runs runtime: launch/Stop/lookup ambiguity becomes durable uncertainty. Detached timer/read/output persistence failures affect runtime health and shutdown. Cleanup attempts all active computer handles, preserves primary/cleanup errors, and releases resources after asynchronous failure. Pending preparation rejection is observed during close.
- runs ACP: stream failure closes/rejects pending requests; tool errors are explicit RPC errors. The immediately attached empty rejection observer avoids an unhandled rejection while write awaits; the original rejecting promise is returned unchanged. It is not a success/empty-data fallback.

Check: bun run check:consistency records the current catch/rejection count. Counts are an inventory, not semantic certification.
Regressions: tests/connection-http.test.ts; tests/connections.test.ts MCP cleanup; tests/content-transport.test.ts temporary public-file unavailable; tests/runtime.test.ts cleanup across two active computers.
