# Content backend evidence

The content lane extends baseline `03192913bfc93a733e721d270b5cd1c98c0a2c34` without changing the generated product UI. Tests run against the actual Hono transports, Better Auth sessions, Bun HTTP/WebSocket server, PostgreSQL and pg-boss admission transaction. PostgreSQL uses a disposable private Unix socket with TCP disabled. Artifact tests use explicitly named in-memory stores, including one that overwrites keys. They do not qualify Garage durability or native execution.

`bun --bun vitest run` passed 66 tests across 8 files. The 47 baseline tests remain included. `tests/content-transport.test.ts` adds 18 scenarios and `tests/artifact-immutability.test.ts` adds one. After the final message-body and bounded-link changes, both content suites were rerun. Exact check commands and summaries are in `content-checks.txt`.

The HTTP scenarios demonstrate authenticated collaborator and viewer behavior, same-origin writes, input bounds, stale Task edits, human ownership, owner eligibility during Project role changes, restricted Document contributor grants, permission-filtered search, keyset pagination over 103 Documents, archive/restore and preserved direct reads. Collection field renames retain stable IDs and values; incompatible schema edits conflict. Proposals leave authoritative content unchanged until human acceptance and reject stale application. Task links do not reveal inaccessible targets, and message capture cannot copy a narrower audience into broader Project Tasks.

Conversation checks cover idempotent delivery, changed reply rejection, explicit mentions, monotonic independent read cursors, attachment references, participant role changes and temporary presence. The actual WebSocket delivers committed Document edits and closes when the selected Document grant is revoked. A published share returns only selected message bodies, without source IDs, reply targets, attachment expansion or private Session data.

Publication requires a saved preview and a separate human action. PostgreSQL JSONB key ordering exposed an initial serialized-comparison error; structural comparison corrected it. Unpublished links return 404, a changed source rejects stale publication, later source edits do not alter published content, an explicit share update replaces the frozen selection, and revocation blocks later reads. Membership loss closes a publisher's existing links. Source-Run publication passes for an eligible human owner and is denied to agent actors, viewers, nonowners and a later member outside the accepted audience. Revoking the publisher's restricted source Conversation closes both the public snapshot and file while private Artifact reads remain denied. File reads check revocation again after storage I/O and validate immutable bytes. An eligible human owner may explicitly publish a selected source-Run Artifact after passing both current source access and the saved Run audience. Private Artifact access remains capped.

Skill import/export exercises the Agent Skills frontmatter format, metadata, a supporting-file path and immutable Artifact ID/hash/length references. The format's `allowed-tools` metadata creates no Connection grants. Actual HTTP Run admission saves those references alongside one pg-boss job; duplicate admission returns the same attempt, and replacing the Document's file selection leaves the accepted Run inputs unchanged. Specification inspected: https://agentskills.io/specification.

The overwriting-store regression records the upload intent before I/O, embeds the SHA-256 digest in its key, simulates a lost upload acknowledgement, rejects changed retry bytes before another storage write, completes the exact retry, preserves retry identity after title/label edits, and verifies legacy-key reads and corruption rejection. This establishes the domain contract, not service-specific conditional-write enforcement.

The Chromium test opens the real published HTML endpoint. The selected heading renders; embedded JavaScript does not run, cookie access raises `SecurityError`, and the attempted Otto API request does not occur. The response has a sandboxed Content Security Policy. `content-share-sandbox.png` shows the rendered file. The browser check covers this fixture and policy, not arbitrary untrusted HTML compatibility.

Biome, strict TypeScript, the 14-package dependency boundary check and the existing production build passed. New `createdAt` and `updatedAt` fields are nullable for historical records; fresh ORM writes populate them. Legacy replay counters keep their SQL `revision` columns while TypeScript and wire records use numeric `cursor`.
