Root cause confirmed in freeze4: `lease.release()` set `released = true` and decremented `reserved` before awaiting `rm`, and a second concurrent call returned immediately, so capacity could read free while the spool file still existed (my earlier reads of this code missed it).
Fix reviewed: `release()` now returns one shared promise; `reserved` is decremented and `released` set only after all `rm` calls succeed; a failed cleanup rejects, clears the shared promise and keeps the capacity held, so a retry re-runs cleanup; a repeat call after success is a no-op. In `deliverFile` the final path now does `await finish()` (cancel reader, delete file, return capacity) before `enqueue(held)`/`close()`, so the body cannot end for the consumer before the lease is joined; `held` is in memory so the last chunk is unaffected.
