## Design decisions for lead integration

- Preserve Agent Profile/Instructions/Model/Skills/Connections groups and Schedule status groups, row composition, detail breadcrumb/right panel/timeline/floating chat. Real configuration has no Agent description/mascot/color, Schedule mock activity or calculated next-run date; remove those mock controls/content. Show the immutable Agent Project and exact Schedule cron/timezone or Manual only.
- Use compact stock New Agent/New Skill/New Schedule dialogs for required setup. Create has no preselected Agent/account/model/output Chat. New Agent scope is workspace or an explicit Project; account models come exclusively from the selected account's gateway.
- Agent's multi-field account/model/Skills configuration and Schedule configuration use explicit fenced Save/Cancel dialogs. One captured opening edit token protects an atomic configuration update, including account/model changes. Skill content and supporting-file mappings save independently, each adopting the acknowledged new token. Ordinary settings outside this lane retain the shared acknowledged autosave design. Lead must record this narrow exception to DESIGN.md's settings-autosave wording.
- Mutations disable controls during pending work; configuration dialogs block Escape/backdrop/close dismissal during writes. Closing without saving cancels local input. Responses acknowledge persisted changes before success toasts/workspace invalidation. Conflicts retain input and instruct closing/reopening to load the latest token.
- Connections are owned server policy, presented through a real link to Connections settings. There is no fake checkbox claiming a grant. The settings lane supplies exact Agent/resource/action/audience grants and revocation.
- Shared `DetailView.more` preserves the existing detail composition with this lane's actual menu. No changes to shared UI tokens/components are included in the lane commit.

## Follow-up self-inspection: concrete findings and corrections

1. **Proposal content looked saved after submission.** A noncreator edited a Skill proposal, submitted it, then the disabled editor retained the proposed title/instructions even though POST only created a proposal. 2. **Lost create ACK allowed a duplicate submission.** Agent, Skill/import and Schedule creates lack a backend request identity. Each form previously allowed the same POST after an undecodable/transport/server error. The current editor now blocks repeat submission for uncertain outcomes, refreshes workspace discovery, retains the draft and explains that the item may already exist. Synchronous submission refs also fence duplicate form events while a write is pending. Explicit API 400/401/403/404/409 refusal remains correctable; no record is claimed created without ACK. Browser verification: intercept the response after persistence, then confirm a second submit sends no POST; close/check discovery before intentional creation. Server idempotency across reopen/reload remains pending.
3. **Uncertain manual Runs stopped polling, and another manual admission stayed reachable.** The Run view now keeps queued/launching/running/uncertain states observed. Its owning Schedule blocks another manual admission until the acknowledged Run is settled and readable; pending Stop and read errors keep that fence. A transport/server/undecodable admission outcome retains the same request UUID and blocks configuration changes until acknowledgement. Archive/disable of an already acknowledged active Run remains explicitly allowed and never claims to stop it. Browser verification: QA 17–18 must exercise uncertainty and Stop recovery.
4. **Reviewed stale-edit/authority behavior retained.** Agent and Schedule editors retain their opening snapshots/tokens; Skill commands adopt tokens only from acknowledged writes. Creator/owner and writer gates do not replace server authorization. No backend/common/router edits, model/account fallback, browser run or heavy suite was added.

5. **Required independent F4 MAJOR: cached private content survived an authoritative denied read.** Agent detail, Skill detail, Schedule detail and Run previously rendered retained `query.data` even after a refetch returned 403/404.
