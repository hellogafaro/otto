# Rendering the design-system sheet

`otto-design-system.svg` is the editable source, generated by `build_sheet.py`
from `tokens.css`. The PNG and PDF are not hand-exported from a design tool —
they were produced by loading the SVG directly in headless Chrome and using
the DevTools Protocol's screenshot and print-to-PDF calls, so every pixel
comes from the same file.

No renderer is vendored into this repository — this is a record of the exact
procedure used, not an added dependency. Any Chrome DevTools Protocol client
(Puppeteer, Playwright, or the raw protocol) can reproduce it.

## 1. Regenerate the SVG after a token change

```sh
cd docs/otto/design-system
python3 build_sheet.py
```

This reads `./tokens.css` and rewrites `otto-design-system.svg` in place. The
script prints the artboard's width and height (currently `1440 3570`) —
needed for the next step if it changes.

## 2. Render the PNG (2× scale) and PDF

Using Puppeteer (or equivalent CDP calls) against the regenerated SVG:

```js
const page = await browser.newPage();
await page.setViewport({ width: 1440, height: 3570, deviceScaleFactor: 2 });
await page.goto("file://" + path.resolve("otto-design-system.svg"));
await page.evaluateHandle("document.fonts.ready"); // wait for the embedded woff2 faces
await page.screenshot({ path: "otto-design-system.png", type: "png" });
await page.pdf({
  path: "otto-design-system.pdf",
  width: "15in",   // 1440px / 96dpi
  height: "37.19in", // 3570px / 96dpi
  printBackground: true,
  margin: { top: 0, bottom: 0, left: 0, right: 0 },
});
```

Width/height in inches are the artboard's pixel size divided by 96 (the CSS
reference DPI). If `build_sheet.py` prints different dimensions, recompute
both values before rendering.

## 3. Chat-sized preview

```python
from PIL import Image
im = Image.open("otto-design-system.png")
w = 900
im.resize((w, int(im.height * w / im.width))).save("otto-design-system-chat.png")
```

## Review record

Independently reviewed (read-only) across three rounds before this sheet was
finalized:

1. **Visual composition** — passed on first review: reads as one coherent
   sheet, no clipping/alignment defect, correct file dimensions (PNG
   2880×7140, PDF one page at 15×37.19in).
2. **Source integrity** — two rounds of findings (a hardcoded color
   dictionary; then remaining hardcoded swatches, contrast-ratio text, and
   status-glyph foreground colors) were fixed so every value in the sheet is
   now read from `tokens.css` at generation time, with contrast ratios
   computed from those same parsed values rather than typed by hand. Final
   round: passed, no remaining findings.

The contrast numbers quoted in [`brand-guidelines.md`](../brand-guidelines.md)
(§3) are computed directly from the hex pairs in `tokens.css` using the
standard WCAG relative-luminance formula — the same formula `build_sheet.py`
uses to print the ratios shown on the sheet itself, so the two stay in sync
by construction rather than by manual bookkeeping.
