# Resources

`@otto/resources` owns saved files and output metadata in `resources`. Current APIs use `/resources`, `resourceId`/`resourceIds`, `resource.create`, and the `resource` Task-link/share discriminator. This is a naming change: the human custodian (`ownerId`), Agent author (`creatorAgentId`), immutable bytes, digest-bound object keys, exact upload retry identity, current membership/Project/visibility and saved/current source-Run audience checks are unchanged. External Connection grant resources and native MCP resource identifiers retain their existing meanings.

Fresh disposable development databases use native `bun db:push`. Existing installations must not accept a destructive drop/create suggestion: stop Otto, inspect and back up the database, and separately review [rename-resources.sql](../scripts/rename-resources.sql) with `ON_ERROR_STOP`. It requires quiescent Runs/released leases, renames the existing table/constraints/indexes and Document/message attachment columns in place, and changes only ordinary Task-link `artifact` discriminators to `resource`. Conflicting/mixed schema state refuses atomically. No file is copied or deleted; queue tables are untouched. There is no startup conversion or numbered migration. The older Skills transfer procedure expects Resources attachment columns; perform this rename first on a pre-Resources populated schema.

Accepted Run Skill files deliberately retain private `artifactId` keys (and the earlier `documentId` Skill identity). New Skill selection is projected to that same immutable accepted shape, so existing private Session bindings/retained execution-scope strings stay exact. The owning Skill getter projects old stored supporting references to public `resourceId`; ambiguous dual identities refuse. The Run file getter returns only current Resource vocabulary while reauthorizing accepted bytes. Stored share `artifact`/`artifactType` JSON projects to `resource`/`resourceType` on reads, preserving frozen selection/preview/snapshot bytes until an explicit human share update/publication/revocation. These are private storage boundaries, not public aliases. Old routes, tool names and request keys are retired.

The procedure is qualified only on private disposable PostgreSQL with controlled storage. It does not authorize or certify a live transfer, provider isolation, Garage or billing. Historical evidence retains the old vocabulary and reviewed revision. The Chat rename in [rename-chats.sql](../scripts/rename-chats.sql) runs after the Resources and Schedules renames and the Skills/Tasks transfers.
