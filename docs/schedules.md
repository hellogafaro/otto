# Schedules

`@otto/schedules` owns reusable prompt/script execution configuration in `schedules` and delivery outcomes in `schedule_history`. A Schedule is not a human Task: it retains a human owner, Agent, output Chat, body, optional Task association and cron/timezone. Project derives from the output Chat. `/schedules` exposes bounded discovery, singular read, create, allowlisted edit-token update, history and explicit manual run. Public references use `scheduleId`/`scheduleEditToken`; there are no Automation aliases.

Disabled suppresses cron, but the eligible human owner can run it manually. Archived rejects new/manual work; restoring leaves it disabled. Enabled cron ticks and queued dispatch check the exact accepted configuration token. Disabling/archive does not implicitly stop active work. Admission remains atomic with its Run job, delivery IDs deduplicate history/retries, and one active Run caps overlap. Scripts need no model account or Session. Existing owner/current Chat/Project/Agent/Task checks remain unchanged.

The owning queue boundary deliberately retains private native pg-boss names `otto-automation-tick` and `otto-automation-schedule`, plus private delivery `automationId`. Both old and new deliveries use that same durable shape; workers pass current `scheduleId` into the domain. No queue rows or native library internals are rewritten. Accepted Run request identities deliberately keep private `conversationId`/`automationId`/`automationEditToken` keys (see [Chats](chats.md)), including on new admissions, so exact old retries still match. Inputs, private Session bindings and retained execution-scope bytes are unchanged. These storage keys are not public aliases.

Fresh development uses native `bun db:push`. For a populated pre-rename database, stop Otto, inspect/back up the database and review [rename-schedules.sql](../scripts/rename-schedules.sql) separately with `ON_ERROR_STOP`. It requires quiescent Runs/released leases; renames the two existing tables, scalar Run/history columns, constraints and indexes in place. It never runs at startup or mutates accepted JSON, native queue schedules/jobs, IDs, ownership, configuration tokens or history outcomes. Do not approve a destructive drop/create suggestion. Conflicting/partial state refuses atomically. The supplied procedure is qualified only on disposable private PostgreSQL, not a live transfer or compute/provider deployment.
